== Flake workflow

Styx is distributed as a Nix flake. There is no standalone `styx` binary anymore:
building, testing, and most day-to-day tasks are ordinary Nix flake commands on
your site (or on the styx flake itself).

=== The styx flake

The styx repository exposes the following outputs:

`lib`::
  The styx library (`styxlib`), passed into a site's `site.nix`.

`legacyPackages.<system>.styxthemes`::
  The bundled theme package set. A site's `flake.nix` typically passes this into
  `site.nix` as `styxthemes`.

`packages.<system>.docs`::
  The styx manual as HTML.

`templates.default`::
  Scaffold for a new site (`nix flake init -t github:styx-static/styx#default`).

`templates.sample-data`::
  Sample pages and posts to merge into an existing site
  (`nix flake init -t github:styx-static/styx#sample-data`).

`templates.theme`::
  Scaffold for a new local theme
  (`nix flake new themes/my-theme -t github:styx-static/styx#theme`).

`checks.<system>.*`::
  The styx test battery. Run everything with `nix flake check` in the styx
  repository.

==== Reading the documentation

[source, bash]
----
$ nix run github:styx-static/styx#doc
----

This opens the built HTML manual in your default browser.

To build the docs without opening them:

[source, bash]
----
$ nix build github:styx-static/styx#docs
$ xdg-open ./result/index.html
----

=== A site's flake

A styx site is a normal Nix flake. The template `flake.nix` wires `site.nix`
into packages and apps.

==== Building

`nix build`::
  Build the site. The output is symlinked at `./result`.

`nix flake check`::
  Build the site and fail if it does not build. Useful in CI.

==== Local preview and checks

These apps are defined in the site template's `flake.nix` and use small
helpers from `styx.lib.apps`:

`nix run .#serve`::
  Build the site (with `siteUrl` overridden for local browsing) and serve it
  with link:https://caddyserver.com/[Caddy] on `http://127.0.0.1:8080`.

`nix run .#linkcheck`::
  Build the site, serve it locally, and run link:https://github.com/lycheeverse/lychee[lychee] against it.

NOTE: `serve` and `linkcheck` use Caddy with default settings. For production,
use a properly configured web server instead.

==== Deploying to GitHub Pages

`nix run .#deploy-gh-pages`::
  Build the site and commit it to a `gh-pages` branch in a `./gh-pages` git
  worktree. The worktree is created on first run and updated in place on later
  runs.

Push manually when ready:

[source, bash]
----
$ git -C gh-pages push -u origin gh-pages
----

See the <<Deployment>> section for more detail.

==== Scaffolding

`nix flake init -t github:styx-static/styx#default`::
  Create a new site in the current directory.

`nix flake init -t github:styx-static/styx#sample-data`::
  Add sample content under `data/sample/` in an existing site.

`nix flake new themes/NAME -t github:styx-static/styx#theme`::
  Create a new theme skeleton under `themes/NAME/`.

=== Overriding configuration at build time

Site configuration is merged from theme defaults, `conf.nix`, and an optional
`extraConf` argument to `site.nix`. The site template's `flake.nix` uses
`extraConf` to build a `preview` package with a local `siteUrl` for
`apps.serve` and `apps.linkcheck`.

To pass other overrides from the command line, rebuild with a custom Nix
expression or adjust `flake.nix`. There is no `--drafts` or `--arg` wrapper
anymore; pass `extraConf` directly when importing `site.nix`.

=== Previewing bundled theme examples

Each theme in `styxthemes` ships an example `site.nix`. During styx
development these are exercised by `nix flake check`. To inspect a built
example locally:

[source, bash]
----
$ nix build github:styx-static/styx#checks.x86_64-linux.showcase-site
$ nix shell nixpkgs#python3 -c python3 -m http.server 8080 --directory ./result
----

Replace `showcase-site` with any theme check name (`ghostwriter-site`,
`hyde-site`, etc.).
