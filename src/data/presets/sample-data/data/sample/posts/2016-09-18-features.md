This post introduces Styx's main features.

<!--more-->

## Clean separation of concerns

A styx site is mainly managed in `site.nix` and `conf.nix`, wired by a `flake.nix`.

- The `data` section loads external files and declares site data.
- The `pages` section declares pages that `mkSite` will render.

Theme configuration uses NixOS-style modules in `conf.nix` (`config.theme.*`, `config.siteUrl`, …).

## Themes

Themes provide templates, static files, optional `lib.nix` helpers, and a configuration module.

Only `generic-templates` ships with this Styx fork; themes combine by listing them in order of increasing priority.

## Content

Styx handles Markdown, AsciiDoc, and `.nix` data files.

Markup files can declare metadata (front matter) and split content with dedicated separators.

Nix can be embedded in markup to include media or other dynamic fragments.

## Template engine

Templates are Nix functions returning HTML strings or page attribute sets.

```nix
''
  <h1>Foo</h1>
  ${templates.bar}
''
```

Use `lib.mapTemplate` to render a list of items.

## Configuration interface

Theme options are declared with `mkOption` in theme `conf.nix` files and merged with `lib.evalModules`.

## Interactive debugging

Use `nix repl` to inspect a built site:

```sh
$ nix repl
nix-repl> pkgs = import <nixpkgs> {}
nix-repl> styx = builtins.getFlake "github:styx-static/styx"
nix-repl> site = import ./site.nix { inherit pkgs; styxlib = styx.lib.${pkgs.system}; }
nix-repl> site.conf
```

## Documentation

Build the manual from the styx flake:

```sh
$ nix build github:styx-static/styx#docs
$ xdg-open result/index.html
```

## Deployment

Site flakes can expose `nix run .#serve`, `nix run .#linkcheck`, and `nix run .#deploy-gh-pages` using helpers from `styx.lib.apps`.
